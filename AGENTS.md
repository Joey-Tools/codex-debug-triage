# Repository Guidance

- This public repository owns an optional, public-safe artifact transport helper and its offline tests. Keep generic diagnosis, forge-specific CI triage, tracker lookup, and private deployment policy outside this skill.
- Keep remote examples synthetic. Do not add company-internal hosts, job names, credentials, credential discovery, or tests that contact a real service.
- Remote policy is fail-closed: fixed HTTPS hosts and auth profiles belong in source, authenticated redirects stay on the same effective HTTPS origin, and command-line limits may only tighten hard ceilings.
- Persistent output protects destination absence, publisher-created object identity, completed byte length, and the selected traditional owner/mode/sticky access policy. Device/inode comparisons establish identity; expected size establishes completed length; regular-file type and mode `0600` establish the selected output policy; parent device/inode plus mode/owner/group establish the bound parent and its selected policy. Under traditional mode semantics, the full path chain rejects unsafe writable directories and prevents an untrusted principal from replacing entries between checks. Root and processes running as the current effective UID are trusted principals; cleanup does not claim conditional-unlink protection against either. Extended ACLs are not inspected, so callers must not choose an output chain whose ACL grants another principal read, add, delete, or write access. Directory timestamps and link counts are deliberately not compared because unrelated child-entry churn does not change those protected properties.
- ZIP acquisition protects the bounded private snapshot as the stable object used for validation. Device/inode bind the opened source object; initial size caps the copy; size and modification time detect ordinary concurrent-change signals. Those signals do not prove source-content stability against a writer able to mutate bytes and restore metadata, so all copied bytes remain untrusted input. Later pathname replacement cannot change the acquired private snapshot. Keep open/read failure, acquisition revalidation failure, and content-signal mismatch distinct.
- Receipt cleanup is attempted after enforced deadlines, worker failures, and Python-level parent interruption; missing exact receipts remain `inconclusive`. Abrupt parent termination that cannot run cleanup is outside the guarantee and may leave a helper-created private temporary file or a fully published final file; it never makes overwriting an existing destination acceptable.
- Network tests use local fakes and never contact a real service. ZIP and filesystem cases use task-scoped local fixtures only.
